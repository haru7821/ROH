# 03. 기술 스택 & 아키텍처 (Unreal Engine 5)

## 1. 엔진 선택: Unreal Engine 5

| 항목 | 선택 | 이유 |
|------|------|------|
| 엔진 | **UE5 (5.4+)** | 쿼터뷰 ARPG에 필요한 렌더링/애니메이션/이펙트 완비, GAS로 스킬 시스템 구축 최적 |
| 언어 | **C++ (코어) + Blueprint (콘텐츠/이펙트 연결)** | 성능 크리티컬한 스탯/드랍 계산은 C++, 반복 작업은 BP |
| 스킬 프레임워크 | **GAS (Gameplay Ability System)** | 어빌리티·쿨다운·자원·버프(GameplayEffect)·태그 체계를 검증된 구조로 제공 |
| 데이터 | **DataTable + PrimaryDataAsset** | 스킬/아이템/접사/몬스터를 데이터 주도로 관리 |
| 입력 | **Enhanced Input** | 클릭 이동 + 스킬 단축키(마우스/QWER/1~4 물약) 매핑 |
| 저장 | **SaveGame 객체 + 버전 필드** | 로컬 세이브, 마이그레이션 대비 |
| 이펙트 | **Niagara** | 스킬 이펙트, 히트 이펙트 |
| AI | **Behavior Tree + EQS** | 몬스터 AI (추적/공격/특수 패턴) |

### GAS를 쓰는 이유 (핵심 결정)
스킬트리·버프·시너지·장비 스탯이 전부 얽히는 ARPG에서 GAS가 제공하는 것:
- **GameplayAbility** = 스킬 1개 (비용/쿨다운/발동 조건 내장)
- **GameplayEffect** = 버프/디버프/도트/스탯 보정 (룬워드 옵션, 오라, 정복자 노드 전부 이걸로 표현)
- **GameplayTag** = 피해 유형/상태이상/시너지 조건의 공통 언어
- **AttributeSet** = 스탯 정의 + 최종값 집계 파이프라인
- 멀티플레이 확장 시 리플리케이션이 이미 내장 → 전략 3(확장성)과 부합

## 2. 프로젝트 구조

```
ROH/
├── Source/
│   └── ROH/
│       ├── Core/           # 게임모드, 게임인스턴스, 세이브 시스템
│       ├── Character/      # 플레이어/몬스터 베이스, AttributeSet
│       ├── Abilities/      # GAS 어빌리티 베이스, 스킬 구현
│       ├── Items/          # 아이템 인스턴스, 접사 생성기, 룬워드 판정
│       ├── Loot/           # 트레저 클래스, 드랍 롤러
│       ├── Progression/    # 스킬트리, 정복자, 경험치
│       └── UI/             # HUD, 인벤토리, 스킬트리 UI (UMG 연동)
├── Content/
│   ├── Data/               # DataTable/DataAsset (스킬, 아이템, 접사, TC, 몬스터)
│   ├── Blueprints/         # BP 서브클래스 (스킬 FX 연결 등)
│   ├── Maps/               # 마을, 필드, 던전
│   ├── UI/                 # UMG 위젯
│   └── FX/                 # Niagara
└── docs/                   # 설계 문서 (본 문서들)
```

## 3. 핵심 시스템 아키텍처

### 3.1 스탯 계산 파이프라인
```
기본 스탯 (레벨 + 수동 분배)
  → [GameplayEffect] 장비 접사 (Additive/Multiplicative)
  → [GameplayEffect] 스킬 패시브/오라
  → [GameplayEffect] 정복자 노드
  → [GameplayEffect] 일시 버프/디버프
  = 최종 스탯 (AttributeSet 집계)
```
- 모든 보정은 GameplayEffect로 통일 → 출처 추적/제거 용이
- 장비 탈착 = 해당 GE 부여/제거

### 3.2 아이템 생성 흐름
```
드랍 이벤트 → TC 추첨 → 베이스 결정 → ilvl 산출 → 등급 판정
→ (유니크: DT_Uniques 조회 | 레어/매직: 접사 풀에서 굴림)
→ FItemInstance 생성 {BaseId, Quality, ilvl, Affixes[], Sockets[], Seed}
```
- 아이템은 **데이터 정의(Base) + 인스턴스(굴림 결과)** 분리
- Seed 저장으로 재현 가능한 굴림 (디버깅/검증용)

### 3.3 룬워드 판정
```
소켓 삽입 시:
1. 베이스가 일반 등급 + 소켓 수 일치 확인
2. 삽입된 룬 ID 시퀀스 == DT_Runewords 레시피 순서 비교
3. 일치 → 아이템에 룬워드 GE 세트 부여, 이름/색상 변경
```

### 3.4 스킬트리 & 시너지
- 트리 상태는 `Map<SkillId, HardPoints>` 로 저장
- 시너지 계산은 어빌리티 발동 시점에 하드 포인트 조회 → 피해 계수 적용
- +스킬 장비는 GameplayEffect로 소프트 레벨 가산

### 3.5 세이브 데이터
```
USaveGame 파생:
- SaveVersion (마이그레이션용)
- 캐릭터 슬롯: 레벨/경험치/스탯 분배/스킬트리/인벤토리/장비/퀘스트/웨이포인트
- 계정 공유: 스태시, 정복자 레벨/분배
```

## 4. 성능 가이드라인

- 화면 내 몬스터 50+ 기준으로 설계 (핵앤슬래시 물량전)
- 몬스터 스폰은 오브젝트 풀링
- 투사체/이펙트 Niagara 풀링, 히트 판정은 단순 셰이프 오버랩
- 드랍 아이템 지면 표시는 경량 액터 + 이름표 UMG 배칭
- 타겟: 1080p 60fps (중급 사양 PC)
